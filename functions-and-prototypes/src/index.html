Immutability

It's a state in which the data we use cannot be modified once created. When using immutability, the only way to change a value is to create a new variable, copying the original and replacing only the fields we care about.

Immutability is not something built into the language by default — it's simply a pattern we can choose to follow:

JavaScript's 7 primitive types are immutable by nature. Structural types (objects, arrays) are not — they require deliberate implementation on our part.

What does it mean that primitives are immutable?

If you assign the same primitive value (e.g. the number 4) to two different variables, both variables point to the same location in memory, since that value cannot be changed in place.

This

this refers to whoever invokes the function — its execution context. It's a pointer, and we can tell it where to point. By default, in the browser, it refers to the global context (the window object).

Manipulating a function's context: call, bind and apply

Call & Apply

Both let you pass a context for that specific invocation. The difference lies in how additional arguments are provided:

  • call. Arguments are passed as individual comma-separated values.
  • apply. Arguments are passed as an array.

Bind

Permanently attaches a function to a given context — no matter how or when you call it.

Functions & Arrow Functions

  • functions. Callable constructs that accept arguments and can return values.
  • arrow functions. A function expression stored in a variable, introduced in ES6.

Functions are first-class citizens

This means functions can be used like any other value:

  1. You can store functions in variables.
  2. You can pass functions as arguments.
  3. You can return functions from other functions.

Differences between function and arrow function

Arrow functions were introduced as part of ESNext (all ECMAScript versions above ES5, i.e. ES6+).

  • In classic functions, this is resolved at runtime (runtime binding) — the execution context is determined when the function is called.
  • In arrow functions, this is resolved at definition time. The this never changes — it's always bound to the context where the arrow function was declared.

Arrow Functions & Async code

Asynchronous callbacks are invoked by the global context. Before ES6, to use the correct this inside an async callback you had to either store the context in a variable or use bind.

Arrow function limitations

  1. The arguments keyword is not available. Classic functions expose an arguments object with all passed arguments; arrow functions do not.
  2. They cannot be used as constructors. Because their this is fixed at definition time, it can never be bound to a new object created with new.
  3. They cannot have a prototype. Arrow functions have no __proto__ property, since they have no constructor.

Prototype Model

JS does not provide a native class model or implementation — it's a dynamic language built around objects, meaning everything is an instance in memory.

What is the difference between a class and an object?

  • A class is a blueprint from which instances are built. As a blueprint, it doesn't exist at runtime — only on paper. The shape is always the same, but the content may vary.
  • An object is the real-world materialisation of that blueprint. You can create as many objects or instances as you like.

In JS, everything is an object — an instance. There are no blueprints (or classes) in the traditional sense.

Prototype

It's where all reusable functions for a type should be defined, so every instance shares the same reference in memory rather than holding its own copy.

What does new do?

  1. Creates an empty object that the constructor function will shape.
  2. Makes that empty object invoke the constructor function (setting this to it).
  3. Links the prototype of the constructor function to the new instance.
